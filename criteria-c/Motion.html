C1 · Logical plan

Plan the data journey before you code. Unlike the light sensor, a PIR gives a digital signal (0 or 1), so the interesting data is how long it stays on.

1 · SensePIR output on GPIO 27 is HIGH (1) when it sees movement
→
2 · DecideESP32 measures dwell time and picks a Status
→
3 · ActRelay (GPIO 25) switches the lights, buzzer (GPIO 26) can alert
→
4 · CollectPython reads one line per second and saves a CSV
→
5 · Derivepandas adds Rolling_Activity and Duty_Cycle_Pct
→
6 · Chart & decide6 figures, then a decision for the school

    Downloads & running it for real
    

    When you have the kit, the real files below do exactly what the simulator showed.
    

    
⬇ motion-sensor.ino (ESP32 sketch)
⬇ 1_data_collection_motion.py
⬇ 2_clean_analyse_motion.py

⬇ motion_telemetry_data.csv (real raw)
⬇ motion_telemetry_clean.csv (real cleaned)
    

    Running it on the real kit
    1. Put motion-sensor.ino in a folder called motion-sensor, open it in the Arduino IDE, choose your ESP32 board and port, and upload. Wait for the 3-second PIR warm-up.
    2. Run pip install pyserial pandas numpy matplotlib seaborn.
    3. Close the Serial Monitor, set SERIAL_PORT in script 1, run it, walk past the sensor, then press Ctrl+C.
    4. Run python 2_clean_analyse_motion.py then python 3_visualize_motion.py.
    Wiring (check your kit's guide): PIR VCC → 5 V (HC-SR501) or 3V3 (AM312), GND → GND, OUT → GPIO 27. Relay on GPIO 25, buzzer on GPIO 26.
